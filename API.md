# MFS Assets API and webhooks

> Online version with screenshots: https://managedfreescout.com/support/mfsassets-api/
> Generated from the manual's source document; do not edit this file by hand.

## Getting started

The MFS Assets API extends FreeScout's own REST API. It needs FreeScout's official **API & Webhooks** module and an active MFS Assets licence; without a licence every call answers `402`.

**Keys and access.** Use the same API keys as FreeScout's API, in the `X-FreeScout-API-Key` header (or `?api_key=`).

- The **main API key** of the API & Webhooks module acts as an administrator: it sees and changes everything.
- A **personal API key** acts as its agent: it sees the assets of the organisations that agent may see, changes them only with the permission "Users are allowed to manage assets", and deletes only when the agent is an administrator.

**Conventions** (the same as FreeScout's API and the MFS Organisations API): JSON in and out, camelCase field names, lists under `_embedded` with a `page` block, a `Resource-ID` header on create, `204` without body on delete. Dates are `YYYY-MM-DD`, times ISO 8601 in UTC.

**Errors** have one shape:

```json
{"message": "Status must be one of: ordered, in_stock, in_use, in_repair, retired, disposed",
 "_embedded": {"errors": [{"path": "status", "message": "Status must be one of: …", "source": "JSON"}]}}
```

| Code | When |
| --- | --- |
| 400 | A field is missing or not valid (see `path`) |
| 401 | No or a wrong API key |
| 402 | No active MFS Assets licence |
| 403 | The key's agent lacks the permission |
| 404 | Asset not found, or not visible to this key |

## Endpoints and the asset object

| Method and path | What it does |
| --- | --- |
| `GET /api/assets` | List assets. Filters: `search` (tag, name or serial, partial), `tag`, `serial`, `status`, `ownerId`, `typeId`, `locationId`, `assignedEmail`, `conversationId`. Paging: `page`, `pageSize` (default 50, at most 200). Sorted by tag. |
| `GET /api/assets/{id}` | One asset. `?embed=history,conversations` adds `_embedded.history` (newest first) and `_embedded.conversationIds`. |
| `POST /api/assets` | Create an asset (needs "manage assets"). Answers `201` with the asset and a `Resource-ID` header. |
| `PUT` / `PATCH /api/assets/{id}` | Change an asset; only the fields you send change. |
| `DELETE /api/assets/{id}` | Delete an asset with its history and files (administrators only). To keep the history, PATCH the status to `retired` or `disposed` instead. |
| `POST /api/assets/{id}/conversations` | Link a conversation: `{"conversationId": 123}`. Answers `201` with all `conversationIds`. |
| `DELETE /api/assets/{id}/conversations/{conversationId}` | Unlink a conversation (`204`; `404` when it was not linked). |
| `GET /api/assets/types` | The asset types with their own fields (`key`, `label`, `type`, `options`). |

**The asset object**

| Field | Type | Notes |
| --- | --- | --- |
| `id` | integer | Read only |
| `tag` | string | Read only, given on create (AST-0001) |
| `name` | string | Required on create |
| `typeId`, `type` | integer, string | `type` (the name) is read only |
| `status` | string | `ordered`, `in_stock`, `in_use` (default), `in_repair`, `retired`, `disposed` |
| `ownerId`, `owner` | integer, object | An MFS Organisations organisation; default the installation's own organisation. `owner` (`id`, `name`) is read only |
| `assignedEmail` | string or null | The person who uses it |
| `assignedDepartmentId` | integer or null | A department of the owner |
| `locationId`, `locationPath` | integer, string | A location of any visible organisation; `locationPath` ("Head office › Building A") is read only |
| `serial`, `supplier`, `notes` | string or null |  |
| `purchaseDate`, `warrantyEnd` | date or null | `YYYY-MM-DD` |
| `purchasePrice` | number or null |  |
| `fields` | object | The type's own fields by key, for example `{"ram": "16 GB", "encrypted": true}`; send only the keys you change |
| `webUrl` | string | The asset page in FreeScout |
| `createdAt`, `updatedAt` | date-time |  |

**Assigning.** Send `assignedEmail` to give the asset to a person, `assignedDepartmentId` for a department, or `"assignedTo": "none"` (or one of the two as `null`) for nobody. A person and a department exclude each other.

## Examples

Replace `helpdesk.example.com` with your FreeScout address and `$KEY` with an API key.

**Find an asset by serial number**

```bash
curl -s "https://helpdesk.example.com/api/assets?serial=7HQ2MZ3" \
  -H "X-FreeScout-API-Key: $KEY"
```

```json
{"_embedded": {"assets": [{"id": 12, "tag": "AST-0012", "name": "Dell Latitude 5440 – Sofia",
  "typeId": 1, "type": "Laptop", "status": "in_repair", "ownerId": 1, "owner": {"id": 1, "name": "Acme"},
  "assignedEmail": "sofia.martins@example.com", "assignedDepartmentId": null,
  "locationId": 2, "locationPath": "Head office › Building A", "serial": "7HQ2MZ3", "supplier": "Dell",
  "purchaseDate": "2023-11-20", "purchasePrice": 1129, "warrantyEnd": "2026-11-20", "notes": null,
  "fields": {"ram": "16 GB", "operating_system": "Windows 11 Pro", "encrypted": true},
  "webUrl": "https://helpdesk.example.com/assets/12",
  "createdAt": "2026-11-08T13:19:40Z", "updatedAt": "2026-11-08T13:19:41Z"}]},
 "page": {"size": 50, "totalElements": 1, "totalPages": 1, "number": 1}}
```

**Create an asset** (for example from a purchasing system)

```bash
curl -s -X POST "https://helpdesk.example.com/api/assets" \
  -H "X-FreeScout-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"name": "ThinkPad T14 – Liam", "typeId": 1, "ownerId": 1, "status": "in_stock",
       "serial": "PF4XK2LM", "supplier": "Lenovo", "purchaseDate": "2026-11-08", "purchasePrice": 1389,
       "fields": {"ram": "32 GB"}}'
```

**Hand it out and move it** (logged as assigned, moved and status changed)

```bash
curl -s -X PATCH "https://helpdesk.example.com/api/assets/10" \
  -H "X-FreeScout-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"assignedEmail": "liam.patel@example.com", "locationId": 2, "status": "in_use"}'
```

**Link a conversation**

```bash
curl -s -X POST "https://helpdesk.example.com/api/assets/10/conversations" \
  -H "X-FreeScout-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"conversationId": 2}'
```

## Webhooks

Webhooks are sent by the API & Webhooks module: choose the events in its webhook settings (**Manage → API & Webhooks**). That module sends them in the background, signed, with its own retries and log.

| Event | When | Payload |
| --- | --- | --- |
| `asset.created` | An asset is created (screen, import, API) | The asset object |
| `asset.updated` | Any change is saved | The asset object |
| `asset.assigned` | It changed hands (person or department) | The asset object |
| `asset.moved` | Its location changed | The asset object |
| `asset.status_changed` | Its status changed | The asset object |
| `asset.deleted` | An administrator deleted it | `id`, `tag`, `name` |
| `asset.linked` | It was linked to a conversation (also by a QR report) | `id`, `tag`, `name`, `conversationId` |
| `asset.unlinked` | It was unlinked from a conversation | `id`, `tag`, `name`, `conversationId` |

One save can send several events: handing out a laptop sends `asset.assigned`, `asset.moved` and `asset.status_changed` (when those changed) and then `asset.updated`. Listen to `asset.updated` alone if you only want to keep a copy in sync.

**Conversation webhooks** (`convo.created`, `convo.updated` and the others) get an extra field with the linked assets:

```json
"assets": [{"id": 9, "tag": "AST-0009", "name": "MacBook Pro 14\" – Emma"}]
```
